# Architecture rules

- Keep full investor-portal authorization and video-portal authorization as separate `user_roles` values because administrators must grant either experience independently.
- Stream investor videos only through the authenticated `investor-videos` Edge Function because Google Drive identifiers and files must never be exposed directly.
- Route native video requests through the scoped service worker so browser range requests stay authenticated without exposing session tokens in media URLs.
- Read current video roles and individual grants concurrently for each request without caching authorization; cache only CORS preflight permission to reduce streaming round trips without delaying revocation.
- Derive admin status lights and audit date ranges through pure helpers from recorded logins, invite timestamps, and current access; missing activity must never be presented as a failed password attempt.
- Refresh admin recent-activity lights with read-only session/page-view queries; expire recent activity rather than claiming live presence from historical records.- Serve Project Run HTML pages only through the authenticated `project-pages` Edge Function into a sandboxed iframe because Drive files and folder ids must never reach browsers.
- Document profile grants: an `investor_profile_access` row with no `investor_document_access` rows means the whole folder; any item rows restrict that person to those folders/files, enforced in `investor-drive`, because admins need both whole-folder and per-file sharing.
- Documents and Project 3D Demo files may be preloaded in the browser and cached briefly in their Edge Functions, but authorization is rechecked on every request and no content is sent before checks pass, because speed must never weaken access control.
- Public share links (`/share/:slug`) go only through the `share-link` Edge Function: password checked server-side (personal no-password links require typing the recipient email, alert the creating admin on a new IP, are tied to one named recipient, always expire, and are emailed only by an admin click), short-lived signed tickets, expiry and on/off rechecked on every content request, because links work without accounts and Drive ids must stay hidden.
- Activity alert emails are sent only by `notify-activity` to the address stored in `activity_watchers` for that person, deduped server-side, because alerts must never reach admins or anyone not chosen.
- Activity map: activity_locations rows written only by notify-activity/share-link Edge Functions, admin-read only, because IP/location is sensitive.
- Share-link administration uses the current server-validated admin role, never creator ownership, because every admin must manage the same link list; the creator only determines new-IP alert delivery.
- Newsletter signup records are read through admin-only RLS while public submission remains insert-only, because newsletter names and emails are private.
- View-as-user runs in a separate tab with the real admin session unchanged; every protected material request independently validates the caller's admin role and the target's current grants, and preview routes suppress writes, activity, and emails because preview must never impersonate credentials or inflate user history.
- Video service-worker credentials are scoped to the requesting browser client rather than shared between tabs, because admin preview and normal playback must remain isolated.
- Admin preview exposes the unchanged dashboard only for a server-validated target admin; a preview-scoped request allowlist blocks all application mutations and emails while keeping catalogs, filters, and navigation available.
